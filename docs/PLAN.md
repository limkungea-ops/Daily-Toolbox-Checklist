# Daily Toolbox Checklist 안드로이드 앱 기획안 (v1.0)

작성: 2026-11-26 / 상태: 기획 확정, 개발 착수 전

## 1. 현상 (문제 정의)

- 매일 Tool Box 사용 전/후 수량 점검을 Google Form(웹)으로 입력한다.
- 매번 같은 값(Tool Box No, Hold Count, Shift 등)을 반복 입력하고, 체크박스를 선택해야 한다.
- 당일 입력을 놓치면 별도 "매뉴얼 입력 시트"에서 수동 입력해야 로그에 기록된다.
- 목표: 입력을 설정값 자동 채움 + 1~2탭으로 줄이고, 누락을 알림으로 방지한다.

## 2. 원인 분석 (기존 폼 구조)

기존 점검 페이지는 **회사 Google Workspace 로그인이 필요한 Google Form**이다.
폼은 응답자 이메일을 수집하므로 로그인 세션 없이 외부에서 직접 POST 할 수 없다.

| # | 항목 | 유형 | 규칙 | 폼 entry ID |
|---|---|---|---|---|
| 1 | 이메일 | 체크박스 | 응답에 기록할 이메일 (필수) | (폼 내장 필드) |
| 2 | Tool Box No | 드롭다운 | 약 123개 중 선택 | entry.2099377435 |
| 3 | Before / After | 라디오 | 필수 | entry.1506871634 |
| 4 | Day / Night Shift | 라디오 | 필수 | entry.419958790 |
| 5 | Hold Count | 정수 | 필수, 정수만 | entry.1109690147 |
| 6 | Abnormal | 정수 | 필수, 이상 없으면 0 | entry.1266075164 |
| 7 | 사용자 | 텍스트 | 선택, 한글 최대 4자 (미입력 시 이메일 사용자명) | entry.180368103 |
| 8 | 유형 | 라디오 | 분실공구 / 파손공구 / 대여공구 / Finding / 기타 | entry.2074485093 |
| 9 | Remark | 긴 텍스트 | 분실 공구가 있으면 필수 | entry.147453066 |
| 10 | 메일전송 | 체크박스 | Tool 담당자에게 특이사항 메일 전송 | entry.703810429 |

> 위 entry ID는 저장된 폼 스냅샷(MHT)에서 추출했다. 폼이 수정되면 ID가 바뀔 수 있으므로 앱에서는 설정 파일로 분리한다.

## 3. 확정 사항 (오라이언 결정)

- Tool Box는 **1개**만 사용한다 (프로필 전환 기능 불필요).
- 연동은 **1차: 미리채움 URL 방식 → 2차: WebView 자동 제출**로 진행한다.
- "이메일 응답 기록" 체크와 "메일전송" 체크는 **설정 화면에서 선택**하도록 한다.
- 제출 후 **Tool Box 자체 로그 시트**를 앱에서 바로 표시한다.
- 개발은 Claude Code 탭에서 진행한다.

## 4. 조치 내용 (앱 설계)

### 4.1 설정 화면 (한 번 저장하면 계속 자동 입력)

| 설정 항목 | 설명 |
|---|---|
| Tool Box No | 저장값이 점검 화면에 자동 입력 |
| Hold Count | 저장값이 자동 입력 |
| Shift (Day/Night) | 기본값 저장 (점검 화면에서 변경 가능) |
| 사용자 이름 | 한글 4자 이내 검증 |
| 이메일 응답 기록 | ON/OFF |
| 메일전송 | OFF / 항상 ON / Abnormal > 0 일 때만 ON |
| 알림 시각 | 사용 전/후 점검 알림 시각 |

### 4.2 점검 화면 (매일)

- 매일 정하는 값: **Before/After**, **Abnormal 수량**
- 나머지는 설정값으로 자동 채움 (Shift 는 필요 시 변경)
- Abnormal > 0 이면 유형 선택과 Remark 입력을 필수로 강제 (폼 규칙과 동일)
- 제출 버튼 한 번으로 폼 제출 단계로 이동

### 4.3 연동 단계

1. **1차 (미리채움 URL)**: 앱이 값이 채워진 폼 주소를 만들어 로그인된 Chrome 으로 연다. 사용자는 제출만 누른다.
2. **2차 (WebView 자동 제출)**: 앱 내 WebView 에서 최초 1회 회사 계정 로그인 후, 값 자동 입력과 제출까지 진행한다.
3. 제출 완료 후 Tool Box 로그 시트를 앱에서 표시한다.

### 4.4 누락 방지

- 지정 시각까지 기록이 없으면 푸시 알림
- "매뉴얼 입력 시트" 바로가기 버튼 (누락일 보충)

## 5. 재발 방지 대책 (리스크)

| 리스크 | 대책 |
|---|---|
| 폼 구조 변경으로 entry ID 변경 | entry ID 를 설정 파일로 분리하고 MHT 재분석 절차를 문서화 |
| 회사 로그인 정보 노출 | 앱이 비밀번호를 저장하지 않고 Google 로그인 세션만 사용 |
| 회사 URL/시트 주소 노출 | 폼/시트 URL 은 저장소에 커밋하지 않고 로컬 설정(`local.properties`)으로 주입 |
| 중복 제출 | 같은 날짜/구분(Before·After) 제출 이력을 앱에서 확인해 경고 |
| 분실 입력 누락 | Abnormal > 0 일 때 유형, Remark 필수 검증 |

## 6. 기술 스택

- Kotlin, Jetpack Compose
- 설정 저장: DataStore
- 알림: WorkManager + Notification
- 배포: APK 직접 설치 (개인 사용)

## 7. 개발 일정

| 단계 | 내용 | 예상 |
|---|---|---|
| 0 | 폼 구조 분석 (완료) | - |
| 1 | 프로젝트 골격, 설정 화면, 점검 화면, 미리채움 URL 제출 | 2~3일 |
| 2 | 알림, 로그 시트 표시, 중복 제출 경고 | 1~2일 |
| 3 | WebView 자동 제출 | 2~3일 |

## 8. 미결 사항

- 로그 시트와 매뉴얼 입력 시트의 앱 내 표시 방식 (WebView 또는 Chrome 탭)
- WebView 자동 제출 시 회사 보안 정책(Workspace 보안 설정) 확인
